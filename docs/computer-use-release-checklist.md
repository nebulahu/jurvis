# Jarvis Computer Use 发布门禁

本文档定义 CU-015 的基准工作流、应用边界和发布检查。桌面控制默认关闭；任何真实 Windows 应用操作都必须由用户确认后执行。

## 记事本端到端基准

目标：验证“启动、聚焦、输入、验证”的 P0 路径，不依赖坐标点击。

单次流程：

1. 确认 `JARVIS_DESKTOP_CONTROL_ENABLED=true`，且 `JARVIS_ALLOWED_APPLICATIONS` 包含 `记事本`。
2. 使用 `open_application` 启动记事本，并经过 L2 确认。
3. 使用 `list_windows` 找到允许列表内的记事本窗口。
4. 使用 `focus_window` 聚焦目标窗口，并验证返回 `success`。
5. 使用 `inspect_window` 读取 UIA 快照，定位支持 `Value` Pattern 的普通文本编辑控件。
6. 使用 `set_element_value` 写入非敏感基准文本，例如 `Jarvis baseline 2026-07-28`。
7. 执行动作后必须重新读取 UIA 状态或窗口状态；验证失败时结果必须是 `ambiguous` 或 `failed`，不能报告成功。
8. 记录审计日志中的风险等级、动作状态、验证状态和耗时。

发布前人工门禁：

- 连续执行 20 次记事本基准。
- 成功率不低于 95%。
- 任何窗口关闭、前台丢失、超时、验证失败或用户取消都必须记录。
- 人工验收不得自动保存文件，不得点击系统级确认框，不得操作允许列表以外窗口。

## Obsidian 工作流边界

原则：Obsidian 优先使用 CLI、文件接口或 Vault 内 Markdown 编辑；桌面控制只作为 UI 兜底。

示例策略：

1. 读取或写入项目记忆时，优先直接编辑 `E:\CodexLib` 下的 Markdown 文件。
2. 创建项目记忆必须包含 frontmatter、wikilink、callout 和验证结果。
3. 需要更新索引时，优先修改 `E:\CodexLib\20-项目\Jarvis\Jarvis 项目总览.md`。
4. 只有在用户明确要求检查 Obsidian 阅读视图、插件行为或 UI 状态时，才考虑桌面控制。
5. 通过桌面控制操作 Obsidian 前，仍必须满足允许应用、前台绑定、确认和审计要求。

## 浏览器工作流边界

原则：浏览器自动化优先 DOM、CDP、浏览器插件或站点 API；桌面控制只作为最后兜底。

边界：

- 读取网页内容优先使用 HTTP、DOM 或浏览器专用能力。
- 点击网页按钮优先使用 DOM 选择器或浏览器自动化。
- 只有 DOM/CDP 不可用、且用户确认需要视觉兜底时，才使用目标窗口截图和受限坐标点击。
- 坐标点击必须绑定有效截图；旧截图、越界坐标、窗口移动或前台丢失必须拒绝。
- 登录、支付、发布、删除、上传等高影响网页动作必须按 L3 逐次确认；密码、支付凭据等按 L4 拒绝。

- 操作后置条件验证测试。
- 取消与紧急停止测试。
- Provider 不支持视觉时的降级测试。
- 旧截图、越界坐标和窗口变化拒绝测试。

## 失败恢复演练

发布前至少覆盖以下失败路径：

- 用户按 Esc 或请求取消后，本轮后续桌面动作返回 `cancelled`。
- 目标窗口关闭时，控制器设置取消令牌并拒绝后续桌面动作。
- 用户抢回前台时，动作拒绝或返回歧义，不继续输入。
- UIA 动作执行失败时返回 `failed`。
- 动作已发出但无法验证时返回 `ambiguous`。
- 图像输入未开启或未授权时，Provider 在网络请求前拒绝。
- 模型服务不支持视觉时返回 `unsupported_feature`。
